L6 — Topological Sort

Graphs track · lesson 6 of the main line · ~30 min · 2026-09-24 · prereq: L4 — BFS: Layers Are Distances, L5 — Boundary Inward (directed edges) · drill: 0012-topo-sort-drill.py · reference: Topological sort

The problem first — getting dressed

Six things to put on: socks, underwear, shirt, pants, shoes, belt. Five rules, each of the form "X before Y":

  • underwear before pants
  • pants before shoes  ·  socks before shoes
  • pants before belt  ·  shirt before belt
Give me one order to put all six on that breaks no rule.

Draw each rule as an arrow from X to Y. That is a directed graph: the one-way edges from L5, now with no grid underneath.

The Python docs define the last one in exactly these terms:

"A topological order is a linear ordering of the vertices in a graph such that for every directed edge u -> v from vertex u to vertex v, vertex u comes before vertex v in the ordering."
— graphlib, Python docs (verified 2026-09-24)

Try your BFS first

You own a traversal that starts from a set of vertices: L4's multi-source BFS. The sources are the obvious seeds, since nothing has to come before them. Seed all three, run BFS, and write down vertices in the order they're popped. Seeds in the order socks, underwear, shirt:

Output: socks, underwear, shirt, shoes, pants, belt. Shoes before pants breaks "pants before shoes".

What went wrong BFS queues a vertex on its first arrival. That was right for distance, where the first arrival is the shortest path. Here it's wrong: socks reached shoes first, and BFS let shoes in while pants still hadn't happened. Shoes needs all its predecessors done, so it has to wait for the last one.

The fix: count what's still missing

"Wait for the last arrival" needs a number per vertex: how many predecessors haven't been output yet. At the start that number is the in-degree. Every time a vertex is popped, each of its successors has one fewer thing to wait for. When a count reaches 0, that vertex is ready and joins the queue.

That is the whole algorithm, known as Kahn's algorithm. Sedgewick & Wayne describe it in an exercise:

"Remove a source from the queue and label it. Decrement the entries in the indegree array corresponding to the destination vertex of each of the removed vertex's edges. If decrementing any entry causes it to become 0, insert the corresponding vertex onto the source queue."
— Sedgewick & Wayne, Algorithms §4.2, Exercise 4.2.7, "queue-based topological sort" (verified 2026-09-24)

You build adj and indeg in one pass over the edge list. One difference from L1: an edge u→v is directed, so it goes into adj[u] only. No mirror entry in adj[v]. Writing that pass is the first drill function.

The answer isn't unique. Underwear, shirt, socks, pants, belt, shoes is valid too. Any order that satisfies the definition counts, which is why the drill checks the definition instead of comparing against one fixed list.

When no order exists

Someone adds a sixth rule: shoes before pants.

Pants must come before shoes and shoes before pants. Following the arrows, pants → shoes → pants gets you back where you started. That is a directed cycle:

"A directed cycle is a directed path (with at least one edge) whose first and last vertices are the same. A directed acyclic graph (or DAG) is a digraph with no directed cycles."
— Sedgewick & Wayne, Algorithms §4.2 (verified 2026-09-24)

No order can satisfy this. CP-Algorithms gives the one-line reason: on a cycle through a and b, "a needs to have a smaller index than b (since you can reach b from a) and also a bigger one (as you can reach a from b)" (Topological Sorting). And without a cycle, an order always exists:

The theorem "A digraph has a topological order if and only if it is a DAG." — Sedgewick & Wayne §4.2

So what does Kahn's loop do on this graph? Trace it:

PopDecrementsReached 0Queue after
—start: pants 2 · shoes 2 · belt 2socks, underwear, shirt
socksshoes 2→1—underwear, shirt
underwearpants 2→1—shirt
shirtbelt 2→1—empty

The loop just stops. No error and no infinite loop. Three vertices were popped, and pants, shoes and belt are each left at count 1. Pants waits for shoes and shoes waits for pants, so neither can go first and neither count reaches 0.

Look at the belt Belt is not on the cycle, and it's still stuck. Its predecessor pants never gets popped, so belt's last requirement is never met. The vertices left over are the cycle plus everything downstream of it. They aren't just the cycle.

Compare with L4, where the neighbour checks totalled 2E because an undirected edge sat in both endpoints' lists. Directed edges are stored once, so the count is E.

Two different "reverse"s — don't merge them

There's a second route to a topological order, and you'll see it in every other source: run DFS, record each vertex when its call finishes, then read that list backwards. That list is the postorder, and "Reverse postorder in a DAG is a topological sort" (Sedgewick & Wayne §4.2). You don't need it for the roadmap, since Kahn's does the same job. What you need is to keep its name apart from L5's:

NameWhat gets reversedAre the edges touched?
transpose GT (L5)the direction of every edgeyes, the neighbour condition is rewritten
reverse postordera list of vertices, in the order DFS finished themno, the graph is left alone

Before you say "reverse" out loud, name what is being reversed. In P7 you got stuck trying to invert "something". This is the same trap.

The stdlib already ships this

graphlib.TopologicalSorter (3.9+). Here's its done() method, from inspect.getsource on 3.14:

for successor in nodeinfo.successors:
    successor_info = n2i[successor]
    successor_info.npredecessors -= 1
    if successor_info.npredecessors == 0:
        self._ready_nodes.append(successor)

That's your loop, with npredecessors as the in-degree. Note how its input is written, though:

>>> from graphlib import TopologicalSorter
>>> g = {"pants": ("underwear",), "shoes": ("pants", "socks"), "belt": ("pants", "shirt")}
>>> list(TopologicalSorter(g).static_order())
['underwear', 'socks', 'shirt', 'pants', 'shoes', 'belt']

Each key maps to its predecessors: "the values are iterables of all predecessors of that node in the graph". That's the opposite of an adjacency list, which maps each vertex to its successors. Same graph, arrows written from the other end. Add the shoes-before-pants rule and it raises CycleError('nodes are in a cycle', ['pants', 'shoes', 'pants']).

For the roadmap problems, write it yourself; that's the mission. In production code, use graphlib.

Check yourself

Your BFS put shoes before pants. What went wrong, exactly?

BFS queues on the first arrival, and socks got there first. Shoes has two predecessors, and Kahn's count makes it wait for the second.

On a DAG, how many times does indeg[v] -= 1 run in total?

A directed edge u→v lives only in adj[u], and adj[u] is read once, when u is popped. On a DAG every vertex is popped, so every edge is decremented exactly once: E.

You add "shoes before pants". What does Kahn's loop do?

Counts only go down, and a vertex enters only at 0. On the cycle nobody reaches 0, so nothing new is queued and the queue runs dry. No error and no infinite loop.

Why is belt never popped, even though it's on no cycle?

A vertex is released by its incoming edges. One of them comes from pants, which sits on the cycle and is never popped, so belt's count stops at 1. Being stuck spreads downstream from a cycle.
