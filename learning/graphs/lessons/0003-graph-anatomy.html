L1 — Graph Anatomy: Build the Map

Graphs track · lesson 1 of the main line · ~25 min + drill · 2026-08-17

The problem first — five people, four friendships

A tiny social network. Five people, numbered 0 to 4. Four friendships: 0–1, 1–2, 2–0, 1–3. Friendship is mutual — if 0 is friends with 1, then 1 is friends with 0. Person 4 knows nobody. Drawn out:

That drawing is a graph — the entire object of this track. Every term you'll meet from here on is just a name for something in this picture:

TermIn the picture
vertex (or node)a dot — one person. Plural: vertices. V is the count of them: here V = 5.
edgea line joining two dots — one friendship. E is the count: here E = 4.
neighbors of uthe vertices sharing an edge with u. 1's neighbors: 0, 2, 3.
degree, written deg(u)how many neighbors u has. deg(1) = 3, deg(4) = 0.
undirectededges work both ways — "friendship is mutual" made formal. (One-way arrows, like a Twitter follow, make a directed graph — later in the track.)
isolated vertexa vertex with no edges at all — person 4.

LeetCode never hands you the drawing. It hands you the ingredients to reconstruct it — a vertex count and an edge list:

n = 5                                      # vertices are numbered 0 .. n-1
edges = [[0, 1], [1, 2], [2, 0], [1, 3]]   # each pair [u, v] is one edge

Each inner pair [u, v] says "there is a line between dot u and dot v" — [0, 1] is the 0–1 friendship, and so on. Because this graph is undirected, [0, 1] and [1, 0] would mean the same thing. Vertex 4 appears nowhere in edges — only n = 5 tells you it exists.

Now answer, quickly: who are 1's neighbors?

You already read them off the drawing — but the program has no drawing, only the list. It must scan all of it, checking both ends of every pair: [0,1] yes, [1,2] yes, [2,0] no, [1,3] yes → {0, 2, 3}. That's one full pass over every edge for one question.

Answering "who are u's neighbors?" straight from an edge list with E edges costs:

Every edge must be inspected — u could appear anywhere in the list. Every graph algorithm asks this question thousands of times, so paying O(E) each time is fatal.

A traversal is an algorithm that walks the graph vertex by vertex, following edges. Every traversal you'll write in this track (DFS, BFS, topological sort — all introduced in later lessons) asks "who are u's neighbors?" over and over, thousands of times. The fix is to pay once, up front, to reorganize the data around exactly that question.

The adjacency list: build the map once

An adjacency list maps each vertex to the list of its neighbors. In Python: a dict[int, list[int]]. Build it in two steps — and the order matters:

adj: dict[int, list[int]] = {v: [] for v in range(n)}   # step 1: every vertex exists
for u, v in edges:                                      # step 2: file each edge
    adj[u].append(v)
    adj[v].append(u)      # undirected: friendship goes both ways

Trace it on paper (your method — one row per edge processed):

#Edgeadj after
0— (step 1){0: [], 1: [], 2: [], 3: [], 4: []}
1[0, 1]{0: [1], 1: [0], 2: [], 3: [], 4: []}
2[1, 2]{0: [1], 1: [0, 2], 2: [1], 3: [], 4: []}
3[2, 0]{0: [1, 2], 1: [0, 2], 2: [1, 0], 3: [], 4: []}
4[1, 3]{0: [1, 2], 1: [0, 2, 3], 2: [1, 0], 3: [1], 4: []}

Now "who are 1's friends?" is adj[1] — a dictionary lookup, then you read exactly deg(1) names. No scanning.

The isolated-vertex trap Look at vertex 4: no edges, but it exists — step 1 gave it a key. If you build keys only while walking the edge list (setdefault-style), vertex 4 silently vanishes. Two lessons from now, "count connected components" will need to visit vertex 4; a map that lost it gives the wrong count. Every-vertex-gets-a-key is step 1 for a reason.
Directed vs undirected — one line of difference Directed edge u → v: only adj[u].append(v). Undirected: both appends. That single line is the whole difference, and forgetting which graph you're in is the classic source of "why is my traversal walking backwards?"

The grid: a graph you never build

Seven of your thirteen roadmap problems hand you not an edge list but a grid:

grid = [["1", "1", "0", "0"],
        ["1", "0", "0", "1"],
        ["0", "0", "1", "1"]]     # 3 rows, 4 cols

This is a graph — each cell is a vertex, and its edges go up/down/left/right — but nobody stores an adjacency list for it. The neighbors of (r, c) are computed on demand:

for dr, dc in ((-1, 0), (1, 0), (0, -1), (0, 1)):   # up, down, left, right
    nr, nc = r + dr, c + dc
    if 0 <= nr < len(grid) and 0 <= nc < len(grid[0]):
        ...  # (nr, nc) is a real neighbor

This is called an implicit graph: the structure exists in the rules, not in memory. Same anatomy, zero construction cost.

Python's negative-index trap grid[-1][c] does not raise — it politely returns the last row. So a missing 0 <= check doesn't crash; it silently glues the top of your grid to the bottom, and your island count comes out wrong with no error anywhere. The bounds check must reject negatives explicitly.

How many in-bounds 4-directional neighbors does corner cell (0, 0) of a 3×4 grid have?

Up is (−1, 0) and left is (0, −1) — both out of bounds. Only down (1, 0) and right (0, 1) survive. Corners keep 2, edges keep 3, interior cells keep 4.

The matrix — and when it's the wrong call

The other classic representation is the adjacency matrix: a V×V table where matrix[u][v] is 1 if the edge exists. Compare the costs (this table is the K-cells of your drill — earn it now):

Adjacency listAdjacency matrix
SpaceO(V + E)O(V²)
"Is (u, v) an edge?"O(deg(u)) — scan u's listO(1) — one cell
Visit all neighbors of uO(deg(u))O(V) — walk the whole row, zeros included

The matrix wins exactly one race: the O(1) edge-existence check. It pays for it with O(V²) memory and O(V) per neighbor scan — whether or not the edges exist. Most real graphs are sparse (E far below V²), and traversals ask "visit my neighbors" far more often than "does this one edge exist", so the adjacency list is the default. Reach for a matrix only when the graph is small and dense, or edge-existence checks dominate.

A graph has 10⁵ vertices and 2×10⁵ edges. How many cells does its adjacency matrix hold?

V² = (10⁵)² = 10¹⁰ cells — roughly 10 GB to store 200,000 edges. That is "sparse: E far below V²" in one picture, and why the matrix is the wrong call here.
