Union-Find — cheat sheet

Graphs track · reference · source lesson: L7

When

Undirected cables arrive over time, groups only merge (never split), and you keep being asked "same group?". A fresh BFS per ask costs O(V + E) each time. Union-find answers in effectively O(1). It doesn't fit one-way edges: directed reachability isn't symmetric, so there are no groups to keep.

The structure

class UnionFind:
    def __init__(self, n: int) -> None:
        self.parent: list[int] = list(range(n))    # everyone is their own root
        self.size: list[int] = [1] * n             # trusted at roots only

    def find(self, x: int) -> int:
        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])   # path compression
        return self.parent[x]

    def union(self, a: int, b: int) -> None:
        ra, rb = self.find(a), self.find(b)
        if ra == rb:
            return                                 # already one group
        if self.size[ra] < self.size[rb]:
            ra, rb = rb, ra                        # union by size: ra is the bigger root
        self.parent[rb] = ra
        self.size[ra] += self.size[rb]

    def connected(self, a: int, b: int) -> bool:
        return self.find(a) == self.find(b)

The two fixes

FixWhat it doesWithout it
union by sizethe smaller tree hangs under the bigger root, so depth ≤ lg n (≈ 17 at 100 000)connect 0 with 1, 2, 3, … builds the chain 0→1→2→…, so find is O(n) and the stream costs ≈ n²/2
path compressionafter find(x), every vertex on the path points straight at the rootevery find re-climbs the same links

Compressing find(0) on [1, 2, 3, 4, 4] (the chain 0→1→2→3→4) gives [4, 4, 4, 4, 4]. The recursive find is safe because union by size keeps the recursion ≤ lg n deep. Without union by size, a 100 000 chain blows Python's limit of 1000.

Gotchas

no ra == rb guardsize[ra] += size[ra] doubles the group's size
compress only xthe rest of the path stays long; every call on the way back must write the root
