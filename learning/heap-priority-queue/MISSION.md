# Mission: Heap / Priority Queue (NeetCode roadmap track)

## Why
Gil is working through the NeetCode DSA roadmap and reached the Heap / Priority Queue node. The goal is twofold: build durable CS fundamentals that make him a stronger engineer day-to-day, and be ready for a future interview cycle where leetcode-style problems are the gate. The paid NeetCode course is off the table — this workspace replaces it.

## Success looks like
- Can explain how a binary heap works internally (array representation, sift-up/sift-down, why operations are O(log n)) without notes.
- Can implement a min-heap from scratch in Python in an interview setting.
- Solves all 7 NeetCode heap problems **independently** (hints allowed, solutions never), recognizing the underlying pattern (top-k, two heaps, greedy scheduling, k-way composition) on sight.
- Uses `heapq` fluently: max-heap via negation, tuple priorities, `heapify`, `nlargest`/`nsmallest`.

## Constraints
- ~30 min per study session, daily-ish → lessons must be small; one concept or one problem per session.
- Python is the only language.
- Conversation in Portuguese; all written materials (lessons, references, records) in English.
- **Never give the answer/solution to the 7 roadmap problems.** Teaching leads *up to* each problem; Gil solves it himself. Hints only when asked, escalating gradually.

## Out of scope
- Advanced heap variants (Fibonacci, binomial, pairing heaps) — mention only, never a lesson.
- Heapsort as a sorting-algorithms deep dive (covered only as a curiosity of the structure).
- Other roadmap nodes (graphs, DP, etc.) — separate workspaces if ever needed.
